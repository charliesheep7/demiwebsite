This is the canonical workflow for the existing 09:00 and 21:00 Asia/Shanghai Claude cloud routines in `charliesheep7/demiwebsite`. Keep both schedules enabled. Up to three independently validated assignments per run; quality and distinct intent take precedence over filling the quota. The selector never publishes or calls an AI service: Claude authors and validates each assignment.

## Before writing

1. Start from the latest `origin/main` in a clean checkout. Read this file and `SKILL.md` in this directory. Preserve unrelated changes and never force-push. If a clean update is not possible, report the conflict rather than publishing against stale state.
2. Run `python3 .claude/skills/demimanifest-blog-writer/routine.py --slot morning` for the 09:00 routine, or `--slot evening` for 21:00.
3. Morning selects at most one original German, French and Italian article each, from `keywords-focused-de/fr/it.json`. Evening selects up to three English existing-page updates from `keywords-focused-en.json`. The initial SP guide is already completed. Money and job terms map to existing URLs, not new near-duplicates.
4. These focused files contain the 2026-10-15 country-specific Semrush research, with separate country, volume, KD, secondary terms and observation dates. Never select from `keywords.csv`, `keywords-researched-*.json`, a stale global skill queue, or `--include-legacy`. Never invent volume/KD. Do not use Turkish in this campaign.
5. Re-run the selector after each completed assignment. In the morning, keep a set of locales already attempted this run and never publish a second article for the same locale; skip a locale already published that Asia/Shanghai calendar day by checking current frontmatter/git history. Skip completed `(locale, slug, research_date)` entries in `publishing-completed.json` and verify frontmatter, ledgers and current main before writing. Native published frontmatter also prevents duplicates. If a locale is empty, skip that locale. If all assignments are empty, report `NO_RESEARCHED_ASSIGNMENTS_LEFT` and end without a content commit. Include remaining queue counts and a request for fresh native research in the run summary. Do not silently reuse old angel-number terms or fabricate research to fill a quota.

## Per-assignment writing and release

- **Publish target is `main`.** Cloud sessions start on a `claude/*` working branch, and a push to that branch publishes nothing (2026-10-15 21:00: three refreshes sat on `claude/quirky-ptolemy-5b8c5z` until merged by hand). After each validated per-article commit run `git fetch origin main && git rebase origin/main && git push origin HEAD:main`. Never end a run with content only on a side branch, and never open a PR instead. Only after the push to main succeeds may the receipt say pushed.
- Research the selected native query and primary sources through available WebSearch. Use the supplied keyword, secondary terms, topic, exact `content_path` and `url_path`. Check same-intent existing pages before drafting; skip a conflicting new assignment and record why. Do not turn a refresh into a new URL. Do not merge/delete other articles without evidence.
- Refreshes preserve publication date, slug and canonical. Update `updated` to the actual date only after a substantive edit. Give the reader an immediate useful answer, practical examples and a concrete exercise. Clearly label illustrative examples; no invented studies, testimonials or guaranteed love/money outcomes. SP content respects boundaries and another person's autonomy.
- Native pages are original writing, not bulk translations. Use correct native spelling and same-language internal links. EN/FR/DE/IT product pages are available. Plain Markdown bodies only, no JSX, no duplicate H1, valid quoted YAML. Set the appropriate `topic` (`love`, `affirmations`, `methods`, `money-career`, `signs`).
- The layout supplies both direct app stores and contextual localized CTAs. Do not insert duplicate download buttons or resurrect fixed-30-second/iOS-only/no-affirmations claims. Do not insert unrelated sibling links just to meet a backlink quota.
- Use a relevant owned text-free hero, including `public/images/manifestation-journal.jpg` when appropriate, or generate a real image and verify its file. Avoid English text on native images. Use the exact existing source image on a refresh when suitable. Never write base64 text into a JPG.
- Install dependencies using the committed lockfile when needed. Run `npm run check:seo`, `npm run test:analytics`, and `npm run build`; inspect the target rendered page, links, image, canonical, language and both store links. Do not publish an assignment that fails validation. If cloud network access prevents source verification, preserve an unpublished draft and continue another assignment; do not label unverified sources verified.
- Update the locale's `written.csv` / `written-<locale>.csv` with primary and secondary keywords. Add an entry to `publishing-completed.json` with `locale`, `slug`, `research_date`, `implemented_on`, and an honest `verification` note. This records an implemented assignment, not a guarantee of live delivery. Include the receipt in the same per-article commit so retries do not rewrite the same work. Stage only this article, assets and relevant ledger/receipt. Commit as `blog: <locale>/<slug>` or `blog-refresh: en/<slug>`, and push to main without force; recheck newer remote content and resolve only safe non-conflicting updates before retrying.
- Verify deployment and the canonical production URL `https://www.demimanifest.com` plus `url_path`, and sitemap inclusion. If a push succeeds but deployment cannot be verified, report `PUSHED_LIVE_VERIFICATION_PENDING`; next runs verify this delivery before rewriting anything. Separate implementation status from production status in the receipt/run summary. Do not claim a scheduler “Succeeded” badge proves publication.
- IndexNow is best-effort after the page is live: use the canonical host and the actual locale path, existing deployed key file, one request. Network failures are logged, never treated as Google indexing success; the existing local IndexNow sweep remains separate. Do not change authentication/network security to make a cloud request work.
- If one assignment fails, record its stage and continue other distinct assignments. Retry failed verification rather than replaying an already pushed article. End with keyword, locale, new/update, URL, commit SHA, validation/deployment/IndexNow states and queue runway. No additional scheduled jobs are created.
